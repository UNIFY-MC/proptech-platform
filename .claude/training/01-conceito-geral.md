# 01 — Conceito Geral: AI-first PropTech Agency

> 🎯 **Objectivo:** alinhar mentalmente sobre o que estamos a construir e porquê.
> 📋 **Pré-requisitos:** nenhum.

---

## A pergunta de partida

Como é que uma agência tradicional PropTech (Property Management) se transforma numa empresa onde **AI faz 90% do fulfillment** e tu (Mário, solo founder) consegues escalar a $1M+ ARR sem contratar 30 pessoas?

A resposta tem **4 princípios**.

---

## P1 — Sell outcomes, not tools

> "We charge a lot of money for the outcome generated by those agents." — Serge Gattari (CookAI)

A maioria das integradores de AI hoje cobra por **acesso a tools**:
- "Aqui tens N8N + VAPI + Make · paga-me $300/mês"

Isso é commodity. Make é gratuito. Vapi custa $20/mês. **Não há moat**.

**O modelo Property007** é diferente:
- "Property Prata Owners, eu garanto-te **100 condóminos a pagar quotas no primeiro dia** via fluxo automatizado + comunicação WhatsApp + cobrança bancária. Pagas-me 5% do valor recuperado."
- "Imobiliária X, eu garanto-te **20 leads HVAC qualificados por semana** via scouting Idealista + outreach LinkedIn + AI calling. Pagas-me €500/lead convertido."

O cliente não compra agents. Compra **resultados**.

---

## P2 — Moat = niche data + playbook

> "The technology is worthless. What matters is the niche data and playbook that you acquire." — Serge Gattari `[01:42:06]`

Anyone pode comprar acesso a Claude API. Mas **só tu** sabes:
- Como funciona o Código Civil Português para mora de condomínio (artigo 559 IRC).
- Quais brokers de seguros PT aceitam apólice multi-risco para edifícios anos 80 vs anos 2000.
- Que tipologias de imóveis em Lisboa têm yield > 6% para fix-and-flip.
- Como interpretar uma factura ERSE Mercado para identificar tarifa errada vs PT vs ES.

**Cada skill** que codificas (`verificar-mora`, `simular-tarifas`, `auditar-cobertura`) é **um pedaço do moat**.
**Cada recipe** que compões (`weekly-mora-batch`, `analyse-energy-bill`) é **um playbook completo**.

Quando tiveres 200 skills + 50 recipes específicas PropTech PT, **ninguém te apanha**. Não por tecnologia. Por **judgment encoded**.

---

## P3 — Encode human judgment, not rules

> "Most successful people have so much depth that on the surface you may think 'it's just marketing'. No, no, no. There's levels to skills." — Serge `[01:17:38]`

A diferença entre uma agência média e uma top-tier:
- **Agência média**: tem checklists e SOPs ("envia email 3 dias após primeiro contacto").
- **Top-tier**: tem **judgment** ("envia email **se** o lead respondeu LinkedIn **e** trabalhou em HVAC **e não** é concorrente — senão escala para Diretor Marketing").

Esse judgment vive na **tua cabeça**. O objectivo das skills + recipes é **codificá-lo**.

Exemplo prático em Property007:
- Skill `verificar-mora` não é "lista condóminos com saldo < 0". É:
  - "Lista condóminos com saldo devedor > 60 dias **excepto** os que assinaram acordo plano de pagamento nos últimos 90 dias **e excepto** os que estão em processo judicial (verificar com `compliance-condo`). Para os restantes, ordena por valor descendente."

Cada `if/else` que encodas é **judgment que outras agências não têm**.

---

## P4 — Harness com 3 camadas (Orchestration + Execution + Verification)

> "Every action the agents take needs to be checked before the next one runs." — Serge `[01:14:20]`

**Não é só agentes a fazer trabalho**. É:

```
┌─ ORCHESTRATION ─┐    ┌─ EXECUTION ─┐    ┌─ VERIFICATION ─┐
│ Goal + context  │ →  │ Write/send  │ →  │ Quality check  │
│ from user/cron  │    │ build/tools │    │ benchmark      │
└────────-────────┘    └─────────────┘    └────────────────┘
                                                 │
                                                 ▼
                                          ┌─ next step ─┐
                                          │ pass: continue │
                                          │ fail: retry / human │
                                          └────────────────┘
```

**Property007 já tem isto built-in**:
- **Orchestration**: `recipes.steps[]` com `input` containing `{{vars}}` + `skills[]` + `connectors[]`
- **Execution**: `task-execute` edge fn corre o step via Claude Haiku + tools
- **Verification**: step com `type='human'` (review/approve) ou agent next step verifica output do anterior

Sem **verification**, agents acumulam erros. Com **verification**, a qualidade sobe a cada iteração.

## 3 fases de transformação (90 dias)

> Adaptado da framework Serge Gattari para PropTech PT.

### Fase 1 (Dias 1-30) — Vehicle: encontrar proven demand

- **Objectivo**: validar 1 vertical com 1-2 clientes pagantes
- **Acção**: focar V2 Condomínios (já tens Prata Owners) — usar `daily-maintenance-triage` recipe + `weekly-mora-batch`
- **Métrica**: 80% das quotas recuperadas via automação · 0 horas manuais admin/condóminos

### Fase 2 (Dias 31-60) — Predictable revenue: replicar para 5+ clientes

- **Objectivo**: 5 clientes V2 a pagar % cobrança · 1 cliente V4 piloto
- **Acção**: Onboarding Flow Builder funcional + Reporting dashboard cliente
- **Métrica**: €5K MRR · churn 0 nos primeiros 60d

### Fase 3 (Dias 61-90) — Agentic transformation: 90% AI fulfillment

- **Objectivo**: tu trabalhas só em Strategy + Approvals · resto é automatizado
- **Acção**: Discord/Slack bridge agents · Voice Vapi atendimento V5 · CLI para escalar
- **Métrica**: 90% das tasks completam sem human-in-the-loop · tu fazes 2h/dia review
