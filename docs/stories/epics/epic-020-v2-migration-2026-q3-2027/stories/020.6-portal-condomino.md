# Story 020.6 — Portal Condómino completo (Conta Corrente, Recibos, EV, Mapas)

**Story ID:** 020.6
**Epic:** epic-020-v2-migration-2026-q3-2027
**Fase do plano:** Fase 6 (Portal Condómino público)
**Effort:** 15-20 dias-dev (~5-7 semanas calendário) — **Story mais longa do epic**
**Status:** Draft
**Owner agent:** aiox-dev (lead) + vertical-builder (mobile-first UI) + architect-proptech (token auth)
**Sequence:** Depende de 020.5 mergeado. Pode arrancar paralelo após 020.1 (com risco)

---

## As a

64 condóminos reais da Prata 2A (utilizadores do `apps/v2-condomino-mobile/dist/` actualmente em produção)

## I want

Substituir o portal mobile actual por uma **app React mobile-first** (`apps/v2-condominios-portal/`) com paridade completa: shell mobile com sidebar drawer, **6 rotas** (`/`, `/pendentes`, `/conta-corrente`, `/carregador`, `/documentos`, `/ficha`), **auth** via token URL ou magic-link, **Conta Corrente** completa (extracto + saldos + recibos), **Recibos PDF** (via EF `v2-recibo-pdf`), **Avisos PDF** (via jsPDF), **Carregador EV** com gráfico + leituras, **Mapas** (Orçamento, Quotas, Dívidas, Prestação), **Ficha** editável, **Documentos** institucionais

## So that

Os 64 condóminos continuam a aceder ao seu portal sem reclamações; magic-link funciona igual; recibos PDF batem 1:1 com legacy (compliance AT). Esta Story é a mais arriscada do epic — risco humano máximo (R14)

---

## Acceptance Criteria

### App shell

1. **AC-1** — Nova app workspace `apps/v2-condominios-portal/` criada (Vite + React + Tailwind + `@proptech/ui`).
2. **AC-2** — Mobile-first com sidebar drawer (hamburger menu). Layout responsive até 320px width.
3. **AC-3** — `package.json` independente; pnpm workspace member.

### Auth (2 fluxos)

4. **AC-4** — Token URL `?token=<jwt>` autentica directamente (compat WhatsApp deep links). Reuse infra de 020.1 AC-3.
5. **AC-5** — Magic-link email: condómino insere email → recebe via EF `send-email` → click autentica. Reuse infra de 020.1 AC-2.

### 6 Rotas

6. **AC-6** — `/` (Início): cards "Pendentes" + "CC Saldo Actual" + "Próximas Quotas".
7. **AC-7** — `/pendentes`: lista avisos não pagos + badge contador no topo.
8. **AC-8** — `/conta-corrente`: extracto completo + saldos + lista de recibos com botão "Download PDF".
9. **AC-9** — `/carregador`: gráfico Chart.js de consumo EV + tabela de leituras (`carregadores_contagens`).
10. **AC-10** — `/documentos`: lista de documentos institucionais filtrados RLS por condomínio.
11. **AC-11** — `/ficha`: form editável (nome, email, telefone, NIF, morada) → save via RPC `update_condomino_self`.

### Funcionalidades específicas

12. **AC-12** — **Recibos PDF**: cada recibo na CC tem botão que chama EF `v2-recibo-pdf` (existe em V1) e retorna PDF. Formato visual = legacy (compliance AT auditável).
13. **AC-13** — **Avisos PDF**: cada aviso pendente em `/pendentes` tem botão "Download PDF" gerado client-side via `jsPDF`.
14. **AC-14** — **Log de acessos**: cada navegação registada em `iam.activity_logs` (action = `portal.view.<route>`).
15. **AC-15** — **Mapas** (sub-páginas em `/conta-corrente` ou separadas): Orçamento em Vigor, Quotas por Fracção, Dívidas globais, Prestação Anual.

### Deploy

16. **AC-16** — Projecto Vercel **`proptech-v2-portal-alpha`** criado: Production Branch = `main`, root = `apps/v2-condominios-portal`, preview URL stable.
17. **AC-17** — Manifest PWA + apple-touch-icon. Offline shell básica opcional.

### Smoke test Fase 6 (`V2-MIGRATION-PLAN.md §3 Fase 6`)

18. **AC-18** — 5 condóminos reais (escolhidos por Mário) acedem via magic-link → vêem CC com mesmos valores que legacy.
19. **AC-19** — Recibo PDF Abril 2026 — **diff visual vs legacy aceitável** (Mário valida).
20. **AC-20** — Carregador EV: condómino com fracção 2A006 vê leituras correctas + gráfico.
21. **AC-21** — Ficha: condómino edita o seu próprio telefone → save → admin (Mário em 020.2) vê actualizado.

## Dev Notes

### Ficheiros a tocar (`V2-MIGRATION-PLAN.md §3 Fase 6`)

- **Nova app**: `apps/v2-condominios-portal/` com estrutura Vite standard
- **6 views**: `Inicio`, `Pendentes`, `ContaCorrente`, `Carregador`, `Documentos`, `Ficha`
- **2 auth components**: `MagicLinkLogin`, `TokenLogin`
- **Reuse `@proptech/ui`**: Sidebar, Topbar, Modal
- **PWA assets**: manifest, sw, apple-touch-icon
- **Backend**: ~10 RPCs em `v2_condominios.*` (forward-only)

### Riscos identificados (`V2-MIGRATION-PLAN.md §3 Fase 6 Riscos`)

- **R14 (CRITICAL)**: 64 utilizadores reais — qualquer regressão visível causa reclamações ao Mário em horas. Mitigação: paralelismo prolongado + opt-in switch + beta-testers AC-18.
- **R15**: Magic-link em mobile pode falhar (browsers default diferentes). Testar iOS Safari + Android Chrome + WhatsApp in-app browser.
- **R16**: Recibos PDF têm de bater 1:1 com legacy (formato AT auditável). Mitigação: EF `v2-recibo-pdf` já existe → confirmar formato; Mário valida AC-19.

### Decisões já feitas

- App separada (não rota `/portal` dentro de `apps/v2-condominios/`) — evita bundle bloat + permite branding mobile-first diferente (recomendação do plano).
- Stack idêntica a `apps/v2-condominios/` (Vite + React + Tailwind).
- DNS final = `portal.prataowners.pt` (subdomínio) — recomendado por `V2-MIGRATION-PLAN.md §3 Fase 6`.

### Decisões a tomar

- Lista exacta de RPCs `portal_*` — confirmar com `V2-INVENTORY-COMPLETE-2026-05-24.md` (portal section).
- PWA offline shell: full ou minimal? — Minimal (cache do shell + manifest).
- i18n no portal: PT-only ou PT+EN? — PT-only (utilizadores cond Property 007 são PT).
