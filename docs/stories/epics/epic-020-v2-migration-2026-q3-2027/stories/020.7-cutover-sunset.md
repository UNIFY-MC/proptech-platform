**Effort:** 1 dia cutover + 30-60 dias observação + 1 dia sunset (gated)
**Status:** Draft
**Owner agent:** Mário (decisor único) + aiox-devops (DNS + monitoring) + supabase-designer (read-only mode V2 + sunset)
**Sequence:** ÚLTIMA story do epic. Depende de 020.6 mergeado + 1 semana freeze

---

## As a

Mário Carvalho (solo founder + cliente Property 007 LDA representante)

## I want

Executar o **cutover DNS atómico** (janela de 2h madrugada) que move `prataowners.pt` + `portal.prataowners.pt` do Netlify legacy para Vercel React, observar 30 dias zero-incidents, e finalmente **pausar Supabase V2 legacy** (`eozklslwfaqujaijvdnl`) reduzindo custo recorrente em 25€/mês

## So that

A migração V2 → React fica oficialmente completa. Cliente Property 007 LDA e 64 condóminos passam para o novo stack sem disrupção. Custo Supabase paralelo deixa de ser pago. Backup completo de V2 fica em glacier durante 12 meses (Mário é TOC, prazo legal 5 anos)

## Acceptance Criteria

### 7.1 — Pre-cutover (1 semana antes)

1. **AC-1** — **Freeze de features** em ambos os ambientes (legacy + React). Comms a Mário e a si próprio: "não criar mais bugs".
2. **AC-2** — **Diff final**: query side-by-side V2 ↔ V1 das **10 tabelas críticas**: `extrato_bancario`, `recebimentos`, `faturas_pendentes`, `condominos`, `fracoes`, `documentos`, `seguro_fracoes`, `carregadores_contagens`, `orcamentos`, `audit_log`. **Delta = 0** obrigatório.
3. **AC-3** — **Bridge cron desligada** (V1 passa a ser fonte de verdade primária).
4. **AC-4** — **Backup completo Supabase V2**: `pg_dump` + Storage rsync para glacier (S3 Glacier ou Cloudflare R2 cold).
5. **AC-5** — **Email aos 64 utilizadores** condómino: "Nova versão do portal a 24 de XX. Magic-link continua igual." (template em 020.5 templates).

### 7.2 — Cutover (1 dia, janela 2h madrugada)

6. **AC-6** — **00:00** — Read-only mode no V2 Supabase: revoke INSERT/UPDATE para roles `anon`, `authenticated`.
7. **AC-7** — **00:15** — Final diff V2↔V1 = 0. Se delta ≠ 0 → STOP e fix antes de avançar.
8. **AC-8** — **00:30** — DNS switch:
   - `prataowners.pt` (apex) → Vercel `proptech-v2-alpha` (admin)
   - `portal.prataowners.pt` (subdomain) → Vercel `proptech-v2-portal-alpha`
9. **AC-9** — **01:00** — Smoke test live: login Mário staff + 3 condóminos beta-test.
10. **AC-10** — **01:30** — Email confirmação a Mário + 3 condóminos test.
11. **AC-11** — **02:00** — Cutover done **OU** rollback executado.

### Rollback procedure (<5 min)

12. **AC-12** — **Rollback documentado e testado em dry-run** ≥ 1 semana antes:
    - DNS revert via Netlify (Mário tem painel pessoal)
    - V2 Supabase: revoke read-only flag (volta a INSERT/UPDATE)
    - Comms: email "voltámos à versão antiga, problemas detectados, sem perda de dados"

### 7.3 — Post-cutover (30-60 dias observação)

13. **AC-13** — **Semana 1**: Mário monitoriza diariamente. Bugs → **fix forward** em V1 (NÃO rollback).
14. **AC-14** — **Semana 2-4**: Mário valida workflows mensais (emissão avisos, recebimentos, OCR).
15. **AC-15** — **Dia 30**: Decisão **GO/NOGO** para sunset V2 Supabase (decisão Mário documentada).

### 7.4 — Sunset (gated, +30-60d post-cutover)

16. **AC-16** — Se GO no Dia 30:
    - Freeze writes V2 (já em read-only)
    - **Final dump** → glacier storage
    - **Pause Supabase project V2** (~25€/mês saved)
    - Manter project pausado **12 meses** para auditoria/compliance AT (Mário TOC, prazo 5 anos legal)
17. **AC-17** — Custo Supabase real desce de 50€/mês para 25€/mês (validado na factura seguinte).

### Riscos identificados (`V2-MIGRATION-PLAN.md §3 Fase 7`)

- **R17 (CRITICAL)**: Delta ≠ 0 no diff final → bridge V2→V1 estava dessincronizada → CUTOVER STOP. Mitigação: cron diff diário 1 semana antes apanha problemas cedo.
- **R18**: DNS propagação > 2h → cliente vê site partido. Mitigação: TTL pré-baixar 1 semana antes (TTL=300s); usar Vercel custom domain assignment (sem proxy).
- **R19**: Pausar Supabase V2 acidentalmente antes dos 30d → perda de dados rollback. Mitigação: AC-16 explicitamente gated por Dia 30 GO/NOGO.

## Risk & Rollback

### Risco
- **CRITICAL** — operação de cutover atómica; falha = utilizadores não acedem ao serviço.
- **CRITICAL** — sunset incorrecto = perda de dados de compliance (Mário é TOC).

### Rollback do cutover (<5 min)
1. DNS revert: apex + subdomain de volta a Netlify legacy
2. V2 Supabase: `ALTER ROLE anon GRANT INSERT, UPDATE`; `ALTER ROLE authenticated GRANT INSERT, UPDATE`
3. Email aos 64 condóminos: "voltámos à versão antiga, problemas detectados, sem perda de dados"
4. Post-mortem em 24h: identificar causa + plano de re-cutover

### Rollback do sunset (até 12 meses)
- Supabase project pausado pode ser **resumed** pelo dashboard
- Dados intactos durante pause window
- Restore custa ~1h + 25€/mês resumido
