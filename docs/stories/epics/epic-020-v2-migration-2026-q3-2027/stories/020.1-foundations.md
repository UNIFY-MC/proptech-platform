## Acceptance Criteria

### Auth (3 fluxos completos)

1. **AC-1** — Staff login user/pwd via `iam.staff_login_aliases` funciona com credenciais reais (`BOSSMC`, ou equivalente Mário). Sessão persistida em `localStorage` ou cookie httpOnly conforme `@proptech/auth`.
2. **AC-2** — Magic-link condómino: utilizador insere email → recebe email via EF `send-email` com token assinado → click no link autentica e cria sessão portal cond.
3. **AC-3** — Token URL: query string `?token=<jwt>` na URL autentica directamente (compat com WhatsApp deep links e legado). RPC equivalente a `portal_get_condomino` chamado.

### i18n PT/EN

4. **AC-4** — `src/i18n/pt.json` + `src/i18n/en.json` criados com **~80-100 chaves** cobrindo todos os labels visíveis em `/` e `/prestacao-contas`.
5. **AC-5** — Hook `useT(key)` exportado em `src/i18n/useT.js`. Default = PT.
6. **AC-6** — Toggle EN no Topbar muda **todos** os labels em `/` e `/prestacao-contas` (cross-check manual com legacy).
7. **AC-7** — Lint rule `no-string-literal-in-jsx` activa (custom ou `eslint-plugin-formatjs`) — previne escapes futuros.

### Topbar + Multi-context

8. **AC-8** — Topbar reescrito com: chip multi-condomínio (Prata 2A · Global), chip multi-ano (2024/2025/2026), botão EN/PT, botão PDF, botão Dark/Light, link "Atualizar Extrato" no sidebar footer (placeholder até Fase 3).
9. **AC-9** — `CondominioContext.jsx` criado, segue padrão do `YearContext`. Provider order definido em `App.jsx` (`<CondominioProvider><YearProvider>...`).
10. **AC-10** — Toggle "Global" muda KPIs em `/prestacao-contas`: se só 1 condomínio registado, valor = Prata 2A (sanity check).

### Charts + Drill-down

11. **AC-11** — `chart.js` + `react-chartjs-2` instalados (lazy import para evitar SSR issues Vercel).
12. **AC-12** — `/prestacao-contas` mostra **gráfico de linha** receitas/despesas mensais (12 meses do ano seleccionado).
13. **AC-13** — `/prestacao-contas` mostra **donut chart** despesas por rubrica.
14. **AC-14** — Drill-down do Resumo Financeiro completo (6 linhas: Saldo Final, Dívidas Condóminos, Dívidas Fornecedores, Valores em análise, Valores a devolver, Saldo Financeiro, FCR recebido) — clicar em "Dívidas Condóminos ›" expande sub-tabela; usa `kpis_detalhe` já em uso.

### Smoke test Fase 1 (`V2-MIGRATION-PLAN.md §3 Fase 1`)

15. **AC-15** — Toggle EN no topbar muda todos os labels visíveis em `/` e `/prestacao-contas`.
16. **AC-16** — Charts renderizam com dados reais (não placeholder).
17. **AC-17** — Drill-down resumo financeiro: clicar em "Dívidas Condóminos ›" expande sub-tabela.
18. **AC-18** — Multi-condomínio toggle "Global" funciona (mesmo que com 1 condo registado).
19. **AC-19** — Magic-link flow end-to-end: email enviado → recebido → click → portal cond simulado.

### Tests + DoD

20. **AC-20** — `src/lib/i18n.test.js` testa paridade chaves PT/EN (toda chave PT tem equivalente EN).
21. **AC-21** — Vitest passa (zero falhas no `apps/v2-condominios/`).
22. **AC-22** — Preview Vercel build verde, smoke test live OK, merge a `main` autorizado por Mário.

### Riscos identificados (`V2-MIGRATION-PLAN.md §3 Fase 1 Riscos`)

- **R1**: i18n refactor toca 24 views — fácil escapar strings. Mitigação: lint rule.
- **R2**: Charts em SPA Vercel podem ter SSR issues — fix: lazy import `chart.js`.
- **R3**: `CondominioContext` quebra `YearContext` se mal coordenado — Mitigação: provider order definido + tests.

### Decisões já feitas

- i18n com `useT()` hook (não `react-intl`) — keep simple, sem ICU.
- Charts via `react-chartjs-2` (não Recharts/visx) — consistência com restante stack PropTech.
- Provider order: `CondominioProvider > YearProvider > rest` (CondominioContext mais externo).
- Magic-link token = JWT assinado server-side (não opaco), TTL 7 dias.

## Risk & Rollback

### Risco
- **Médio** — refactor profundo (i18n toca todas as views), mas isolado da Production (até merge).
- Magic-link depende de EF `send-email` configurada com Resend key (confirmado em 020.0).

### Rollback
- Revert merge PR Fase 1 → Vercel rebuild automático → estado anterior restaurado.
- Production só foi tocada no merge a `main` (Regra D2) → rollback = `git revert <merge-sha> && git push`.
- Não há mudanças schema V1 nesta Story (só leitura) → sem rollback DB necessário.
