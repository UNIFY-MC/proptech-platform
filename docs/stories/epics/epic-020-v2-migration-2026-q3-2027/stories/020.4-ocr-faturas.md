# Story 020.4 — OCR Faturas workflow completo

**Story ID:** 020.4
**Epic:** epic-020-v2-migration-2026-q3-2027
**Fase do plano:** Fase 4 (OCR de Faturas)
**Effort:** 8-12 dias-dev (~3-4 semanas calendário)
**Status:** Draft
**Owner agent:** aiox-dev (lead) + supabase-designer (RPC `migrar-fatura` em V1) + architect-proptech (dedup logic)
**Sequence:** Depende de 020.3 mergeado

---

## As a

Mário (admin do condomínio Prata 2A) a processar **faturas de fornecedores que chegam por email/PDF**

## I want

Restaurar o fluxo OCR end-to-end do legacy: **drag-drop PDF**, processamento via EF `ocr-fatura` (já existe em V1), **review modal** com fields detectados editáveis (fornecedor, NIF, número fatura, valor, data, rubrica), **migrar para Faturas Pendentes** via EF `migrar-fatura` (OQ3 resolvido em 020.0), **dedup waterfall** (número fatura + NIF), tabs "Histórico OCR" e "Faturas sem OCR", e **auto-upsert NIF** fornecedor quando OCR detecta NIF novo

## So that

Mário consegue processar 30+ faturas/mês sem voltar ao legacy. Workflow é o coração do trabalho contabilístico (Mário é TOC); regressão = atraso na facturação + risco compliance AT

---

## Acceptance Criteria

### Upload PDF + OCR

1. **AC-1** — Drag-drop em `/faturas` com botão "+ OCR Fatura" (alternativa drag).
2. **AC-2** — POST do PDF para EF `ocr-fatura` (já existe em V1 — confirmado em 020.0 AC-8).
3. **AC-3** — Loading state robusto com realtime subscription a `faturas_ocr` OU poll cada 3s até `status = 'completed'` ou `'error'`.

### Review modal

4. **AC-4** — Modal mostra fields detectados editáveis: fornecedor, NIF, número fatura, valor, data, rubrica.
5. **AC-5** — Edit inline + save → UPDATE em `faturas_ocr` (com `reviewed = true`, `reviewed_by`, `reviewed_at`).
6. **AC-6** — Botão "Migrar para Pendente" → EF `migrar-fatura` (OQ3 resolvido + recriada em V1 se faltava) → INSERT em `faturas_pendentes` + UPDATE `faturas_ocr.migrated_at`.
7. **AC-7** — **Dedup waterfall warning**: query check `(numero_fatura, fornecedor_nif)` em `faturas_pendentes` ANTES de migrar. Se hit → confirm modal "Possível duplicado em fatura ID X de YYYY-MM-DD. Continuar?".
8. **AC-8** — Auto-upsert fornecedor: se NIF detectado não existe em `v2_condominios.fornecedores` → INSERT silencioso (com `created_by_ocr = true`).

### Tabs Faturas

9. **AC-9** — Tab "Histórico OCR" carrega view `v_ocr_historico` (ou query equivalente) com paginação.
10. **AC-10** — Tab "Faturas sem OCR" carrega view `v_faturas_sem_ocr` (faturas em `faturas_pendentes` sem `ocr_id`).

### Smoke test Fase 4 (`V2-MIGRATION-PLAN.md §3 Fase 4`)

11. **AC-11** — Upload fatura PDF real de fornecedor "EDP" → OCR returns campos → review modal mostra valores correctos → "Migrar" → aparece em Faturas Pendentes.
12. **AC-12** — Upload mesma fatura 2x → 2ª vez avisa "Possível duplicado".

### Riscos identificados (`V2-MIGRATION-PLAN.md §3 Fase 4 Riscos`)

- **R9**: OCR async — UX precisa de loading state robusto + retry. Mitigação: realtime subscription ou poll 3s + timeout 60s + retry button.
- **R10**: Dedup waterfall (número + NIF) pode dar falsos positivos. Mitigação: confirm modal sempre (não bloqueia, só avisa).

### Decisões a tomar

- Realtime subscription vs polling? — Realtime se Supabase Realtime estiver activo no schema `v2_condominios`; senão polling 3s (mais simples).
- Dedup key: só `(numero, nif)` ou também `(valor, data)` para apanhar duplicados sem nº fatura? — Recomendação: `(numero, nif)` primary + `(valor, data, nif)` warn secondary.
- Auto-upsert fornecedor: silent vs prompt? — Silent (UX faster) com flag `created_by_ocr` para audit posterior.

## Risk & Rollback

### Risco
- **Médio-Alto** — workflow OCR é coração do trabalho diário Mário; regressão = TOC desligado da realidade fiscal.
- Dedup waterfall pode causar falsos positivos (bloquear migração legítima) — mitigação: confirm modal não-bloqueante.

### Rollback
- Revert merge PR → Vercel rebuild.
- Migration views/RPCs: idempotente (CREATE OR REPLACE) — não destrutiva.
- Faturas migradas durante testes: marcar `is_test = true` e DELETE manual pós-cutover.
