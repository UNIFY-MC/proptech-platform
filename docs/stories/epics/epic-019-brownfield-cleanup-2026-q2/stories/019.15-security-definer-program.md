# Story 019.15 — Programa SECURITY DEFINER (vistas + RPCs + search_path + extensões)

**Story ID:** 019.15
**Epic:** epic-019-brownfield-cleanup-2026-q2
**Covers debts:** DB-002 (Critical), DB-004 (Critical), DB-017 (Medium)
**Effort:** XL (programa de 3-5 semanas)
**Sequence:** Fase C
**Status:** Draft

## As a

Mário e qualquer agente que execute queries com JWT (superfície de ataque actual é enorme — 218 funções + 40 vistas com `SECURITY DEFINER`)

## I want

Programa coordenado para reduzir a superfície SECURITY DEFINER em V1 — search_path fixes (Fase imediata), revogação selectiva de `anon` (Fase 2), conversão para SECURITY INVOKER onde possível (Fase 3) + mover extensões para schema dedicado

## So that

Funções mal escritas não possam exfiltrar dados via SECURITY DEFINER + `pg_net`; vistas SECURITY DEFINER deixem de ser bypass total de RLS; superfície de ataque seja auditável.

## Acceptance Criteria

### Fase imediata — search_path fixes (1 semana)

1. **AC-1** — As 62 funções com `search_path` mutável são corrigidas via `ALTER FUNCTION ... SET search_path = <schema>, extensions;`
2. **AC-2** — Migration `fix_search_path_security_definer_v1.sql` aplicada e auditável em git
3. **AC-3** — Linter `pg_catalog` advisor confirma 0 funções com search_path mutável

### Fase 2 — revogação selectiva de `anon` (2 semanas)

4. **AC-4** — Inventário das 106 funções acessíveis por `anon` documentado em `docs/database/security-definer-anon-audit.md` com decisão por função:
   - **MANTER** (legítima: `core.ask_property007_intent`, `iam.portal_token_login`, V5 magic_link)
   - **REVOGAR** (não deve ser acessível por anon)
5. **AC-5** — Migration `revoke_security_definer_anon_v1.sql` aplica REVOKE conforme decisão
6. **AC-6** — Smoke test REST: chamadas anónimas a funções revogadas retornam 401, chamadas a funções mantidas continuam funcionais

### Fase 3 — converter para SECURITY INVOKER (2-3 semanas)

7. **AC-7** — 40 vistas SECURITY DEFINER convertidas para SECURITY INVOKER (ou justificação documentada para manter):
   - Programa coordenado com RLS (RLS deve estar correcta antes — depende de 019.1)
   - Vistas CRM Attio (`core.list_records`, `core.get_activity_timeline`) — auditar callers
   - Inventário em `docs/database/security-definer-views-audit.md`
8. **AC-8** — 112 funções `authenticated` — auditadas para escalation cross-schema; consolidação onde possível

### Mover extensões — DB-017

9. **AC-9** — Extensões `pg_net`, `unaccent`, `http` movidas de `public` para `extensions`:
   ```sql
   CREATE SCHEMA IF NOT EXISTS extensions;
   ALTER EXTENSION pg_net SET SCHEMA extensions;
   ALTER EXTENSION unaccent SET SCHEMA extensions;
   ALTER EXTENSION http SET SCHEMA extensions;
   ```
10. **AC-10** — `pgrst.db_schemas` actualizado para incluir `extensions`
11. **AC-11** — Smoke test: funções que usavam `pg_net` continuam funcionais (search_path correcto)
