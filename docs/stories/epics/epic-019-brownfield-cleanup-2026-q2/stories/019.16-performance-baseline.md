# Story 019.16 — Performance baseline (DB index cleanup + FK indexing + bundle audit)

**Story ID:** 019.16
**Epic:** epic-019-brownfield-cleanup-2026-q2
**Covers debts:** DB-009 (Medium), DB-014 (High), FE-015 (High)
**Effort:** L + L + M
**Sequence:** Fase C
**Status:** Draft

## As a

Mário (operações de escrita degradadas a piorar com volume de dados; bundle V5 nunca medido em mobile)

## I want

Cleanup de 341 índices unused em V1, criação de 110 índices FK em falta, e baseline de Lighthouse + bundle size por app

## So that

JOINs cross-schema e DELETEs cascade tenham performance estável com crescimento de dados; CI possa fazer enforce de threshold de bundle size; decisão "V5 mobile-ready?" tenha dados.

## Acceptance Criteria

### DB-009 — cleanup unused indexes

1. **AC-1** — Inventário em `docs/database/unused-indexes-v1-2026-05.md` baseado em `pg_stat_user_indexes` (com pelo menos 30 dias de uptime):
   - 341 índices unused identificados
   - 8 pares de índices duplicados
   - Decisão por índice: DROP / MANTER (justificativo)
2. **AC-2** — Migration `drop_unused_indexes_v1.sql` usa `DROP INDEX CONCURRENTLY` (não bloqueia produção V1):
   ```sql
   DROP INDEX CONCURRENTLY IF EXISTS public.idx_audit_user_id_legacy;
   -- ...
   ```
3. **AC-3** — Smoke test pós-cleanup: linter `unused_index` advisor confirma redução de >250 índices

### DB-014 — criar índices FK em falta

4. **AC-4** — Inventário de 110 FKs sem índice em `docs/database/fk-missing-indexes-v1-2026-05.md`
5. **AC-5** — Migration `create_fk_indexes_v1.sql` cria índices via `CREATE INDEX CONCURRENTLY IF NOT EXISTS`:
   ```sql
   CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_pessoas_organization_id ON core.pessoas(organization_id);
   -- ...
   ```
6. **AC-6** — Smoke test: query EXPLAIN de DELETE cascade ou JOIN representativo usa o novo índice

### FE-015 — bundle audit + Lighthouse baseline

7. **AC-7** — `rollup-plugin-visualizer` configurado em `vite.config.js` de cada app (dashboard, v2, v4, v5, truth)
8. **AC-8** — Build de cada app gera `bundle-stats.html` em `dist/` — baseline documentado em `docs/frontend/bundle-baseline-2026-05.md`:
   - V5 mobile-first: target <300kb gzipped
   - Dashboard: target <500kb gzipped
   - V2 produção: target <400kb gzipped
9. **AC-9** — Lighthouse manual ou via script em cada app (Preview Vercel ou local) — score Performance / Accessibility / Best Practices / SEO documentado
10. **AC-10** — Threshold opcional adicionado ao `pre-push-checklist`: avisar se bundle main chunk cresceu >10% vs baseline
