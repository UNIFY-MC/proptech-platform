# Story 019.8 — Testing baseline Vitest + RTL (dashboard + v5)

**Story ID:** 019.8
**Epic:** epic-019-brownfield-cleanup-2026-q2
**Covers debts:** FE-018 (High)
**Effort:** L
**Sequence:** Fase A (setup) → Fase B (suite mínima)
**Status:** Draft

## As a

Mário (refactor sem rede de segurança é roleta russa) e agentes que vão consolidar design system / auth / routing

## I want

Vitest + React Testing Library configurados em `apps/dashboard` e `apps/v5-manutencao` com suite mínima — smoke tests, auth flow, 1 view principal

## So that

Refactorings da Fase B (auth migration, design system, routing) tenham detecção automática de regressões; novas features tenham padrão de teste a seguir; CI possa correr `npm test` por app.

## Acceptance Criteria

1. **AC-1** — `apps/dashboard/package.json` declara dependências dev: `vitest`, `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`, `jsdom`.
2. **AC-2** — `apps/dashboard/vite.config.js` (ou `vitest.config.js` separado) tem bloco `test:` com `environment: 'jsdom'`, `setupFiles`, `globals: true`.
3. **AC-3** — `apps/dashboard/src/test/setup.js` configura `@testing-library/jest-dom` e mocks globais (Supabase client, router).
4. **AC-4** — Suite mínima em `apps/dashboard/src/**/*.test.jsx`:
   - `App.smoke.test.jsx` — render do App sem crash
   - `AuthGuard.test.jsx` — protege route quando user é null, deixa passar quando user existe
   - `views/Funnel.test.jsx` (ou view principal equivalente) — render + 1 interacção chave
5. **AC-5** — Mesmo setup em `apps/v5-manutencao`:
   - Vitest + RTL configurados
   - Suite mínima: smoke + AuthContext (compat temporária OU `@proptech/auth` após 019.7) + view principal (Catalogo ou Ordens)
6. **AC-6** — `npm test` em cada app corre em <30s e passa 100% verde.
7. **AC-7** — Documento `docs/testing/frontend-baseline.md` com:
   - Como adicionar novo teste
   - Padrões de mock (Supabase, router, env)
   - Como correr em watch mode
8. **AC-8** — Adicionar `npm test` aos scripts de pre-push checklist (ainda não enforced em CI, mas documentado).
