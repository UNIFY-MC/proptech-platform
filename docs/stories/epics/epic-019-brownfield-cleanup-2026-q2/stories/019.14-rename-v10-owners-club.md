# Story 019.14 — Rename schema `v1_owners_club` → `v10_owners_club`

**Story ID:** 019.14
**Epic:** epic-019-brownfield-cleanup-2026-q2
**Covers debts:** DB-005 (Critical)
**Effort:** M
**Sequence:** Fase C (ÚLTIMO de todos os Critical DB)
**Status:** Draft

## As a

Mário e qualquer agente que faça queries `WHERE table_schema LIKE 'v1%'` (apanha schema errado)

## I want

Renomear o schema actual `v1_owners_club` (V10 Owners Club, mapeado erradamente como V1) para `v10_owners_club`

## So that

Naming canónico V10 = Owners Club fique correcto no Postgres; queries de agentes deixem de apanhar Owners Club quando pesquisam V1 Core Hub; CLAUDE.md root e código fiquem alinhados.

## Acceptance Criteria

1. **AC-1** — Diagnóstico de dependências executado e ZERO hits encontrados (ou todos os hits corrigidos antes do rename):
   ```sql
   SELECT routine_schema, routine_name FROM information_schema.routines
   WHERE routine_definition ILIKE '%v1_owners_club%';

   SELECT viewname FROM pg_views WHERE definition ILIKE '%v1_owners_club%';

   -- + grep em código fonte:
   grep -r "v1_owners_club" apps/ supabase/ packages/ docs/
   ```
2. **AC-2** — Migration `rename_v1_owners_club_to_v10.sql` aplicada:
   ```sql
   ALTER SCHEMA v1_owners_club RENAME TO v10_owners_club;
   ```
3. **AC-3** — `pg_dump` antes e depois confirma que as 3 tabelas + 6 rows estão íntegras no schema novo.
4. **AC-4** — Funções e vistas que dependiam (se houver após AC-1) — re-validadas via `\d+ v10_owners_club.*` no psql; sem estado "invalid" em `pg_proc`.
5. **AC-5** — PostgREST exposure actualizada (depende de 019.2): `pg_roles.rolconfig` da role `authenticator` substitui `v1_owners_club` por `v10_owners_club`.
6. **AC-6** — CLAUDE.md root e código actualizados; zero referências a `v1_owners_club` em git após esta story.
7. **AC-7** — Smoke test cross-app: dashboard / ofertas / `/owners` (se existir route) — queries leem do schema renomeado sem erro.

- Mitigação: AC-1 (diagnóstico) **antes** de qualquer rename
